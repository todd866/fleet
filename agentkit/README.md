# agentkit

One operating layer for Claude Code, Codex, and Cursor. The private site lives in
`~/.config/agentkit` (or `AGENTKIT_CONFIG`). This crate is the generator, the schema,
and a sanitized example. It does not contain hosts, addresses, or secrets.

`sync` is a dry-run until `--apply`. Apply copies any replaced file to
`~/.local/state/agentkit/backups/<unix>/` and writes only under `$HOME`. A project
path outside `$HOME` is refused.

## Commands

| Command | What it does |
|---|---|
| `agentkit inventory` | Print [the mechanism inventory](../docs/agentkit/inventory.md). `--out FILE` writes it. |
| `agentkit sync` | Diff the generated provider files. |
| `agentkit sync --apply` | Write them. A second run with no source edit prints `no changes`. |
| `agentkit doctor` | One row per provider. Exit 1 on drift. Writes `doctor.json`. |
| `agentkit doctor --provider cursor` | The same check for one provider. |
| `agent-context` | Posture (per provider), capacity, mail, fleet alerts. `AGENTKIT_PROVIDER` set by hooks. Also `agentkit context`. |
| `agentkit posture write` | Refresh `~/.local/state/ai-budget/posture.json` from `ai-capacity --json`. |
| `agentkit hook <claude\|codex\|cursor> <guard\|all>` | Provider adapter. Tool-call JSON on stdin. `all` runs every enabled guard. |
| `agentkit memory import --from DIR` | Copy Claude `*/memory/*.md` into the notebook. Skips secret-shaped files. |
| `agentkit memory path` | Print the notebook directory. |

Generated hooks call `agentkit` and `agent-context` by name. Both have to be on `PATH`
before `sync --apply`. The global rule file also lists the five prohibitions, for a
surface that never loads its hook file. That text does not enforce them.

Guard binaries, same decision on stdin, neutral JSON on stdout: `guard-hard-delete`,
`guard-icloud`, `guard-offload-heavy`, `guard-cd-outside`, `guard-push`.
`decision` is `allow`, `ask`, or `deny`. A parse error allows, as the hooks they
replace do. The deny rules are not relaxed.

## Site

```
agentkit.toml
rules/global.md
rules/projects/<name>.md
skills/<name>/SKILL.md
memory/INDEX.md
memory/facts/<id>.md
```

Copy `agentkit/example/` to `~/.config/agentkit` and edit it there. Schema:
[`schema/site.schema.json`](schema/site.schema.json). Doctor report:
[`schema/doctor.schema.json`](schema/doctor.schema.json).

Generated files carry `generated by agentkit — edit the source`. Project `AGENTS.md`
is that source for Codex and Cursor. Project `CLAUDE.md` is only `@AGENTS.md`.

## What doctor checks

Rules match the site. Each provider's hook file names all five guards and
`agent-context`. The notebook `INDEX.md` is readable. A built-in self-test still
denies `rm` outside temp, denies `trash ~/Documents`, asks on `git push`, and
denies `git push --force`.

`~/.local/state/agentkit/doctor.json` is what fleet-health and mac-registry read.
`ok: false` becomes a Needs-attention row. Gaps that are limits of a provider
(no status line, no wake-up tool) are listed on the provider and do not fail the exit.

## Guards

| Binary | Answer |
|---|---|
| `guard-hard-delete` | deny `rm` / `find -delete` / `git clean -f` / inline `os.remove` outside temp and scratchpad |
| `guard-icloud` | deny emptying Trash and wiping a whole Desktop, Documents, or iCloud Drive root |
| `guard-offload-heavy` | deny a heavy command when `offload-target` names a worker; fail open if it does not |
| `guard-cd-outside` | deny `cd` to an absolute path outside `guards.allowed_cd` |
| `guard-push` | ask on `git push`, deny `--force` and `-f`, allow `AGENTKIT_PUSH_APPROVED=1` |

The generated hooks run `agentkit hook <provider> all`, which runs these and the guards that
have no binary of their own:

| Guard | Answer |
|---|---|
| `disk-slot` | deny a command that touches `/Volumes/*` unless that command runs under `disk-slot PATH -- ...`; `ls`, `stat`, `df`, `du`, `test`, `[` and `diskutil list\|info\|activity\|apfs list` are exempt |
| `metered-link` | while `~/.local/state/METERED_LINK` exists, deny transfers (`rsync`, `scp`, `curl` to a file, `docker pull`), package restores (`npm ci\|install`, `pnpm`/`yarn install`, `brew install\|upgrade\|fetch`, `pip install`, `uv sync`, `cargo fetch\|install`), `git clone`, `git lfs pull\|fetch` and model pulls (`ollama pull`, `hf download`); `git pull`, `fetch` and `push` are allowed |
| `agent-yolo` | deny raw `agent -p` with `--force` or `--yolo` |
| `test-audio` | deny audible playback unless `AUDIBLE_APPROVED=1` |
| `slot-holder` | deny SIGKILL on heavy-slot by name (`pkill -9 heavy-slot`, `kill -9 $(pgrep heavy-slot)`), here or over ssh, and on a pid that has an entry in this Mac's heavy-slot queue; use `heavy-slot release <pid>` |
| `slot-files` | deny writes to heavy-slot's `limit` and `cool` files: redirect, `tee`, `sed -i`, `cp`/`mv`, an inline script, and Claude's `Write`/`Edit` |
| `approval-files` | deny creating an `APPROVE_*` marker file from a shell (`touch`, redirect, `tee`, `cp`, `mv`, `install`, over ssh too) or with `Write`/`Edit`; the owner creates those |
| `idrive-cleanup` | deny starting IDrive's Archive Cleanup (AppleScript, the client's program, a cleanup script); the patterns are `guards.idrive_cleanup_patterns` |
| `secrets` | deny any command that names a private key (a file in `~/.ssh` that is not public material, an `id_<type>` key anywhere, a `guards.secret_paths` entry), the `~/.ssh` folder, or a glob that reaches one on disk, unless its program uses keys in place: `ssh`, git, `ssh-add`, `ssh-keygen`, `chmod`, `ls`, `stat`, `trash`, `echo`/`agent-mail` (text only), `cp`/`mv` within `~/.ssh`, and `scp`/`rsync`/`sftp` to a fleet Mac with no `-o`/`-F`/`-J`/`-S`/`-e`/`--rsh`. Quotes, `$VAR` assignments and `cd` on the line are followed. Also `Read` and `Grep` of a key or the folder, and a decrypted keychain dump. Deny only, never ask. A tripwire for an agent talked into it, not a sandbox: a script file the agent writes and then runs is not read |

`secrets`, known gaps (review of 16 Nov 2026; evasions by an agent working around the
guard, not normal use): a Grep is judged by its glob's text, not by whether its root holds
`~/.ssh` (multiple globs, `type`, `!` forms); git's path lists read from a file or stdin
are only caught when the line also names a key; `cp`/`mv` with `-t`/`--target-directory`
take the last word as the destination. A shell folder above `~/.ssh` (`find ~`,
`grep -r … ~`) is left open on purpose. Closing these is fine if it costs ordinary work
nothing.

The `icloud` guard denies emptying the Trash on every host, an exempt worker included.
`slot-holder`, `slot-files`, `approval-files` and `idrive-cleanup` work with no site
configuration; `guards.slot_state_dir`, `guards.slot_files`, `guards.approval_file_patterns`
and `guards.idrive_cleanup_patterns` change their defaults. Claude's hook also receives
`Write`, `Edit`, `MultiEdit` and `NotebookEdit` calls, which only `slot-files` and
`approval-files` judge. Codex and Cursor hooks see shell commands only.

How the guards read a command line:

- `slot-holder`, `slot-files`, `approval-files`, `idrive-cleanup` and the Trash check also read
  text that another program on the line may run: a quoted word handed to `watch`, `su -c`,
  `find -exec`, a string in a `python -c` or here-document script, what `echo` prints unless
  the `echo` is the whole line. Mail (`agent-mail send`) and a search pattern or commit
  message are text, for that command only: the rest of the line is still judged.
- A command none of them can read (more than six layers of `sh -c` / `ssh`, a quote that
  never closes) is denied when the line is about that guard's subject, and allowed otherwise.
- `hard-delete` treats a search pattern or a commit message as text only when the whole line
  is one `grep`, `rg` or `git commit|tag|log|grep` command with known options. `echo` and
  `printf` are never text to it.
- A `Write`, `Edit`, `MultiEdit` or `NotebookEdit` call is judged by its path alone, by
  `slot-files` and `approval-files`; its content is not read, and a missing path allows.

A headless worker where Trash is not a recovery path is `guards.air_aliases` /
`guards.air_hosts` in the site. The binary has no built-in hostname. One whole
`ssh <alias> '<command>'` may hard-delete there. Anything after it on the same
line is still checked.

Project-only rules (shared-tree `git add -A`, a worktree `db:seed`) stay in that
project's own hook. This crate does not replace them.

### What the guards do not do

They read a command line; they do not run a shell. They stop the accident and the
plain command, and they refuse a line they cannot read when it is about their
subject. They are not a sandbox, and an agent that sets out to get round one is
breaking the rule that guards are satisfied, never dodged. Known gaps, kept on
purpose because closing them would refuse ordinary work:

- A delete or kill carried by another program's own option or API (a search tool's
  preprocessor option, a pager variable, an interpreter calling `os.kill` or
  `subprocess`) is caught only for the forms listed in the tests.
- A path reached through a variable set earlier (`d=$HOME/Documents; ... "$d"`) or
  through a glob is not resolved.
- Only Claude's file-edit tools are judged by path; the Codex and Cursor hooks see
  shell commands only.
- An approval marker is an honour system: `AGENTKIT_PUSH_APPROVED=1` answers a gated
  push, and a remote branch delete when it prefixes that one command alone on its
  line. It never answers a force push or `--force-with-lease`.

The switch checklist is [docs/agentkit/switch-provider.md](../docs/agentkit/switch-provider.md).
