# agentkit

One operating layer for Claude Code, Codex, and Cursor. The private site lives in
`~/.config/agentkit`. This crate is the generator, the schema,
and a sanitized example. It does not contain hosts, addresses, or secrets.

agentkit finds the account's home in the user database and its config, state folder and
ledger under it. No environment variable moves them (`HOME`, `AGENTKIT_CONFIG`,
`AGENTKIT_STATE` and `AGENTKIT_DECISIONS` did until 28 Nov 2026): a hook inherits its
environment from the agent it guards, so a variable that chose the config let that agent
choose it. `--home DIR` works in another tree (the test suite, trying a site out), and only
with it may `--config DIR`, `--state DIR` and `--ledger PATH|off` be given; for the account's
own home they are refused. The generated hook commands carry none of these flags.

`sync` is a dry-run until `--apply`. Apply copies any replaced file to
`~/.local/state/agentkit/backups/<unix>/` and writes only under `$HOME`. A project
path outside `$HOME` is refused.

## Commands

| Command | What it does |
|---|---|
| `agentkit inventory` | Print [the mechanism inventory](../docs/agentkit/inventory.md). `--out FILE` writes it. |
| `agentkit sync` | Diff the generated provider files. |
| `agentkit sync --apply` | Write them. A second run with no source edit prints `no changes`. |
| `agentkit doctor` | One row per provider. Exit 1 on drift. Writes `doctor.json`. |
| `agentkit doctor --provider cursor` | The same check for one provider. |
| `agent-context` | Posture (per provider), capacity, mail, fleet alerts. `AGENTKIT_PROVIDER` set by hooks. Also `agentkit context`. |
| `agentkit posture write` | Refresh `~/.local/state/ai-budget/posture.json` from `ai-capacity --json`. |
| `agentkit hook <claude\|codex\|cursor> <guard\|all>` | Provider adapter. Tool-call JSON on stdin. `all` runs every enabled guard. |
| `agentkit memory import --from DIR` | Copy Claude `*/memory/*.md` into the notebook. Skips secret-shaped files. |
| `agentkit memory path` | Print the notebook directory. |

Generated hooks call `agentkit` and `agent-context` by absolute path:
`~/.local/bin/agentkit` with `agent-context` beside it, or wherever `hook_bin` in
`agentkit.toml` says (an absolute path; a root-owned folder is the strongest choice). Nothing
on `PATH` can stand in for them, `guard-config` refuses agents writing either file or
removing the folder that holds them, and doctor fails when the hook program is not there.
Install both before `sync --apply`, and run `sync --apply` again after moving them. The
global rule file also lists the five prohibitions, for a surface that never loads its hook
file. That text does not enforce them.

Guard binaries, same decision on stdin, neutral JSON on stdout: `guard-hard-delete`,
`guard-icloud`, `guard-offload-heavy`, `guard-cd-outside`, `guard-push`.
`decision` is `allow`, `ask`, or `deny`.

A hook that cannot do its job refuses the call and records the refusal in the ledger: input
that is unreadable, not UTF-8, not JSON or not a JSON object is `guard-input`; an
`agentkit.toml` that is there but cannot be read or is invalid is `guard-setup`. (The
providers read "no answer" as "no objection", so until 28 Nov 2026 a tool call the parser
rejected was allowed, unrecorded.) With no `agentkit.toml` at all, every guard runs with its
defaults.

## Site

```
agentkit.toml
rules/global.md
rules/projects/<name>.md
skills/<name>/SKILL.md
memory/INDEX.md
memory/facts/<id>.md
```

Copy `agentkit/example/` to `~/.config/agentkit` and edit it there. Schema:
[`schema/site.schema.json`](schema/site.schema.json). Doctor report:
[`schema/doctor.schema.json`](schema/doctor.schema.json).

Generated files carry `generated by agentkit — edit the source`. Project `AGENTS.md`
is that source for Codex and Cursor. Project `CLAUDE.md` is only `@AGENTS.md`.

## What doctor checks

Rules match the site. Each provider's hook file names all five guards and
`agent-context`. The notebook `INDEX.md` is readable. A built-in self-test still
denies `rm` outside temp, denies `trash ~/Documents`, asks on `git push`, and
denies `git push --force`.

`~/.local/state/agentkit/doctor.json` is what fleet-health and mac-registry read.
`ok: false` becomes a Needs-attention row. Gaps that are limits of a provider
(no status line, no wake-up tool) are listed on the provider and do not fail the exit.

## Guards

| Binary | Answer |
|---|---|
| `guard-hard-delete` | deny `rm` / `find -delete` (every start point, `-exec`/`-execdir`/`-ok`) / `git clean -f` / `rsync --del*` / inline `os.remove` outside temp and scratchpad; a program word it cannot read (`$(echo rm)`, `$X` not assigned a literal on the line, `{rm,…}`, a glob); text a shell reads on stdin (`echo … \| sh`, `sh <<< …`); `mv`/`ln` of a non-temp path into temp on a line that deletes there. A temp path with `$` (other than `$HOME`/`$TMPDIR`), a backtick, a brace (`{}` of `xargs -I` included) or `..` is not temp. `rsync --delete`: every operand after the source must be temp or on the worker |
| `guard-icloud` | deny emptying Trash and wiping a whole Desktop, Documents, or iCloud Drive root |
| `guard-offload-heavy` | deny a heavy command when `offload-target` names a worker; fail open if it does not |
| `guard-cd-outside` | deny `cd` to an absolute path outside `guards.allowed_cd` |
| `guard-push` | ask on `git push`, deny `--force` and `-f`, allow `AGENTKIT_PUSH_APPROVED=1` |

The generated hooks run `agentkit hook <provider> all`, which runs these and the guards that
have no binary of their own:

| Guard | Answer |
|---|---|
| `disk-slot` | deny a command that touches `/Volumes/*` unless that command runs under `disk-slot PATH -- ...`; `ls`, `stat`, `df`, `du`, `test`, `[` and `diskutil list\|info\|activity\|apfs list` are exempt |
| `metered-link` | while `~/.local/state/METERED_LINK` exists, deny transfers (`rsync`, `scp`, `curl` to a file, `docker pull`), package restores (`npm ci\|install`, `pnpm`/`yarn install`, `brew install\|upgrade\|fetch`, `pip install`, `uv sync`, `cargo fetch\|install`), `git clone`, `git lfs pull\|fetch` and model pulls (`ollama pull`, `hf download`); `git pull`, `fetch` and `push` are allowed |
| `agent-yolo` | deny raw `agent -p` with `--force` or `--yolo` |
| `test-audio` | deny audible playback unless `AUDIBLE_APPROVED=1` |
| `slot-holder` | deny SIGKILL on heavy-slot by name (`pkill -9 heavy-slot`, `kill -9 $(pgrep heavy-slot)`), here or over ssh, and on a pid that has an entry in this Mac's heavy-slot queue; use `heavy-slot release <pid>` |
| `slot-files` | deny writes to heavy-slot's `limit` and `cool` files: redirect, `tee`, `sed -i`, `cp`/`mv`, an inline script, and Claude's `Write`/`Edit` |
| `approval-files` | deny creating an `APPROVE_*` marker file from a shell (`touch`, redirect, `tee`, `cp`, `mv`, `install`, over ssh too) or with `Write`/`Edit`; the owner creates those |
| `idrive-cleanup` | deny starting IDrive's Archive Cleanup (AppleScript, the client's program, a cleanup script); the patterns are `guards.idrive_cleanup_patterns` |
| `secrets` | deny any command that names a private key (a file in `~/.ssh` that is not public material, an `id_<type>` key anywhere, a `guards.secret_paths` entry), the `~/.ssh` folder, or a glob that reaches one on disk, unless its program uses keys in place: `ssh`, git, `ssh-add`, `ssh-keygen`, `chmod`, `ls`, `stat`, `trash`, `echo`/`agent-mail` (text only), `cp`/`mv` within `~/.ssh`, and `scp`/`rsync`/`sftp` to a fleet Mac with no `-o`/`-F`/`-J`/`-S`/`-e`/`--rsh`. Quotes, `$VAR` assignments and `cd` on the line are followed. Also `Read` and `Grep` of a key or the folder, and a decrypted keychain dump. Deny only, never ask. A tripwire for an agent talked into it, not a sandbox: a script file the agent writes and then runs is not read |
| `guard-config` | deny writes to agentkit's site config (`~/.config/agentkit`, except `memory/`, `skills/`, `rules/*.md`, `rules/projects/` and `paused-providers`), to the hook files the guards run through (`~/.codex/hooks.json`, `~/.cursor/hooks.json`, `~/.gemini/config/hooks.json`) and to the programs the hooks run (`agentkit`, `agent-context`). The rule is by what is touched, not by which program touches it: a command that is not known only to read (`cat`, `grep`, `rg`, `jq`, `diff`, `ls`, `stat`, `shasum`, `sed`/`awk` without in-place or a file named in the script, `find` without `-exec`, `tar` making an archive, the git subcommands that read or record) is refused when any word, option value or assignment in front of it names a protected path exactly, also through a glob the shell would expand, a `for` variable, a literal assignment, or `xargs` fed the path by a pipe. A patch tool's envelope (`*** Update File:`) is judged by the files it names. Every refusal starts `Refused for <path>:` and says why. Text that only mentions a path (a message, a here-document written to a file, a quoted argument) and reads of it are not writes. On top of the general rule: shell writes (redirect, `tee`, `sed -i`, `cp`/`mv`/`ln` onto, moving or removing them or a folder that holds them, `chmod`, a `git` checkout over them, an inline script) and `Write`/`Edit`. `.claude/settings*.json` and `.codex/config.toml` (in any directory, a project's included) take a `Write`/`Edit` that leaves `hooks` and `disableAllHooks` as they are, and for Codex every key at any depth that names hooks or features, and the `profile` selector; `.codex/hooks.json` and `.cursor/hooks.json` in any directory are not written. Shell writes to any of them are denied, and so is a write whose target has a glob, an unresolved `$` or a backtick that could land on one (`~/.c*/…`, `$D/hooks.json`), an output or extract option aimed at one (`-o`, `-O`, `-d`, `-C`, `--output`), with same-line assignments, `cd` and `pushd`/`popd` followed. Any JSON `Write`/`Edit` that adds a `disableAllHooks` is denied |

`secrets`, known gaps (review of 16 Nov 2026; evasions by an agent working around the
guard, not normal use): a Grep is judged by its glob's text, not by whether its root holds
`~/.ssh` (multiple globs, `type`, `!` forms); git's path lists read from a file or stdin
are only caught when the line also names a key; `cp`/`mv` with `-t`/`--target-directory`
take the last word as the destination. Since 21 Nov 2026 an archiver or recursive reader
whose operand holds `~/.ssh` is denied: `tar` members read against its `-C` directory
(`tar -C ~ -cf x .ssh`, `tar -cf x ~`), `zip -r`, `cp -r|-a`, `rsync`/`ditto` to a non-fleet
destination, `grep -r`, `rg --hidden|-u`, `find ~ … -exec`. `find ~` without `-exec`, `du ~`
and `ls -R ~` stay allowed. A glob word longer than 512 characters is refused.

The `icloud` guard denies emptying the Trash on every host, an exempt worker included.
`slot-holder`, `slot-files`, `approval-files` and `idrive-cleanup` work with no site
configuration; `guards.slot_state_dir`, `guards.slot_files`, `guards.approval_file_patterns`
and `guards.idrive_cleanup_patterns` change their defaults. Claude's hook also receives
`Write`, `Edit`, `MultiEdit` and `NotebookEdit` calls, which only `slot-files`,
`approval-files` and `guard-config` judge. Codex and Cursor hooks see shell commands only.
`secrets` also refuses `cred` with any subcommand but `list`, `add`, `import`, `rm` and
`--help` (`_values` prints every password, `fill` hands one to another program), as the
program or as an interpreter's script, over ssh, under wrappers, or fed by `xargs`. `icloud`
refuses `empty-bin` unless it is given `--verified-offloads` or `--dry-run`/`-n`. The worker
exemption of `hard-delete` holds only for a plain `ssh <worker>` whose options are among
`-t -T -q -v -4 -6 -C -n -p PORT`: with any other option, `user@`, a nested `ssh` in the remote
text, or `rsync -e` / `RSYNC_RSH` / `RSYNC_CONNECT_PROG` / `RSYNC_PROXY`, the remote text is
checked like local text. For an interpreter (`python3 -W x cred`, `zsh -o opt empty-bin`), any
word that is the tool, by name or by the file it resolves to, counts as it.

A guard named in `[guards] disabled` fails `agentkit doctor` until the owner accepts it with
`agentkit doctor --accept-guards` at a terminal (stdin and stdout both a TTY, and he types
`accept`; from a hook or an agent's shell it records nothing), which prints what changed in `[guards]` and records a
SHA-256 of the section (keys sorted, layout ignored) in `<state>/guards-accepted.json`. While
that hash matches, the disable is a warning that names the guard; any later change to
`[guards]` while something is disabled fails again until accepted. Agents may not run
`--accept-guards` or write the record: `guard-config` refuses both.

`guard-config` also counts `disableAllHooks` as a parsed key at any depth and in any case,
escapes decoded (loosely, on decoded text, for JSON that does not parse strictly). It treats a
`.claude`, `.codex` or `.cursor` folder itself as protected anywhere, checks where a copy's
source would land (a hook folder merged onto one that exists, or onto home), takes
`-t`/`--target-directory` or any operand after the first as a copy's possible destination
(so a protected file as a second source is refused too), and flags a glob or variable whose
literal part has a hook folder component at any depth, or whose glob component could become one.

How the guards read a command line:

- `slot-holder`, `slot-files`, `approval-files`, `idrive-cleanup` and the Trash check also read
  text that another program on the line may run: a quoted word handed to `watch`, `su -c`,
  `find -exec`, a string in a `python -c` or here-document script, what `echo` prints unless
  the `echo` is the whole line. Mail (`agent-mail send`) and a search pattern or commit
  message are text, for that command only: the rest of the line is still judged.
- A command none of them can read (more than six layers of `sh -c` / `ssh`, a quote that
  never closes) is denied when the line is about that guard's subject, and allowed otherwise.
- `hard-delete` treats a search pattern or a commit message as text only when the whole line
  is one `grep`, `rg` or `git commit|tag|log|grep` command with known options. `echo` and
  `printf` are never text to it.
- A `Write`, `Edit`, `MultiEdit` or `NotebookEdit` call is judged by its path alone, by
  `slot-files` and `approval-files`; its content is not read, and a missing path allows.
  `guard-config` reads the content only for Claude's settings and Codex's config, to see
  whether the edit leaves the hooks alone.

A headless worker where Trash is not a recovery path is `guards.air_aliases` /
`guards.air_hosts` in the site. The binary has no built-in hostname. One whole
`ssh <alias> '<command>'` may hard-delete there. Anything else on the line, before or
after it, and a `"$(...)"` that runs locally inside it, is still checked.

Project-only rules (shared-tree `git add -A`, a worktree `db:seed`) stay in that
project's own hook. This crate does not replace them.

### What the guards do not do

They read a command line; they do not run a shell. They stop the accident and the
plain command, and they refuse a line they cannot read when it is about their
subject. They are not a sandbox, and an agent that sets out to get round one is
breaking the rule that guards are satisfied, never dodged. Known gaps, kept on
purpose because closing them would refuse ordinary work:

- A delete or kill carried by another program's own option or API (a search tool's
  preprocessor option, a pager variable, an interpreter calling `os.kill` or
  `subprocess`) is caught only for the forms listed in the tests.
- A path reached through a variable set earlier (`d=$HOME/Documents; ... "$d"`) or
  through a glob is not resolved.
- Only Claude's and Antigravity's file-edit tools are judged by path, and a patch tool by the
  files its envelope names; any other tool a provider adds is not judged.
- A write whose target is not on the command line: a patch body, a script file, an archive
  unpacked above a protected folder, a path computed at run time. `guard-config` judges
  named paths. The control for the rest is ownership: a root-owned `hook_bin`, and the
  site config and hook files made immutable by the owner.
- A Claude settings edit may change only the top-level keys in `CLAUDE_AGENT_MAY_CHANGE`
  (`generate.rs`: `permissions`, `$schema`, `model`, `effortLevel` and a few plain
  preferences); a Codex config edit only `model`, `model_reasoning_effort` and `personality`,
  at the top level or in a profile. Any other key is refused by name: `hooks`, `env`,
  `disableAllHooks`, the keys that run a program (`statusLine`, `notify`), load code
  (`enabledPlugins`, `mcp_servers`) or set the approval posture, and any key a later release
  adds, are the owner's to change.

Compiled in, the same on every Mac, whatever site config says:

- The keys the guards sign with, `ledger.key` and `tripwire.key` in agentkit's state folder,
  are opened by agentkit and tripwire and by nothing else. `secrets` and `guard-config` each
  refuse a command, a `Read` or a `Grep` that names one, a glob that reaches one, a script
  that opens one, a copy (to another fleet Mac included) and a recursive read or archive of
  the folder they are in. `ls`, `stat` and `wc` on a key, and reading the ledger beside it,
  are fine.
- tripwire's records (`~/.local/state/fleet/tripwire/`) and config
  (`~/.config/fleet/tripwire.json`) are read freely and written only by `tripwire` itself.
- `$TMPDIR` is believed only when the folder it resolves to (symlinks followed) lies inside
  `/tmp` or `/var/folders` and neither is nor holds the home folder; a delete target is
  resolved the same way before it is compared with the temp roots.
- An approval marker is an honour system: `AGENTKIT_PUSH_APPROVED=1` answers a gated
  push, and a remote branch delete when it prefixes that one command alone on its
  line. It never answers a force push or `--force-with-lease`.
